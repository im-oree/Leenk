# Deploying Leenk

Three separate deployments. Keeping them apart is deliberate: the admin console
must not share an origin with the public app, so a compromise of one cannot
reach the other.

| What | Where | Root directory | Config |
|---|---|---|---|
| Student app | Vercel | `/` (repo root) | `vercel.json` |
| Admin console | Vercel (second project) | `admin` | `admin/vercel.json` |
| API | Render | `backend` | `render.yaml` |

Deploy the **API first** — both frontends need its URL at build time.

---

## 1. API on Render

**Blueprint (recommended).** Render → *Blueprints* → *New Blueprint Instance* →
pick this repo. It reads `render.yaml` and creates the service.

**Manual.** New *Web Service* → root directory `backend`, build `npm ci`,
start `npm start`, health check path `/health`.

### Environment variables

`JWT_SECRET` is auto-generated by the blueprint. Set the rest in the dashboard:

| Variable | Required | Notes |
|---|---|---|
| `CORS_ORIGIN` | **yes** | Comma-separated. Must list **both** Vercel URLs, or every browser request fails. |
| `ADMIN_KEY` | **yes** | Without it the entire admin API returns `503 NO_ADMIN_KEY`. Use a long random value. |
| `FIREBASE_PROJECT_ID` | yes | Leenk's **own** project, never StudentHub's. |
| `FIREBASE_CLIENT_EMAIL` | yes | From the service-account JSON. |
| `FIREBASE_PRIVATE_KEY` | yes | Paste with real newlines, or `\n`-escaped — both are handled. |
| `STUDENTHUB_*` | no | Federation stays off until `STUDENTHUB_ENABLED=true`. |
| `PAYSTACK_*` / `FLUTTERWAVE_*` | no | Payments ship disabled. |
| `IMGBB_KEYS` | no | Comma-separated, round-robined. |
| `DEV_OTP_CODE` | **never in prod** | When set it is the *only* accepted OTP — anyone could sign in as anyone. |

Without the Firebase variables the API silently falls back to an in-memory
store that is wiped on every restart and every deploy. It boots and looks
healthy, which makes this an easy mistake to miss — check the boot log for
`store: firestore`.

### Free plan caveat

Render's free tier sleeps after ~15 minutes idle, and the next request pays a
cold start of roughly 30–50s. The client already has timeouts and a circuit
breaker, so the app degrades rather than hanging — but the first visit after a
quiet night will be slow. Upgrade before real users.

## 2. Student app on Vercel

New project → import this repo → framework **Vite**, root directory `/`.

| Variable | Value |
|---|---|
| `VITE_USE_API` | `true` |
| `VITE_API_BASE` | `https://<your-api>.onrender.com/api` |

`VITE_API_BASE` **must be absolute in production.** It defaults to `/api`,
which only works in dev where Vite proxies to localhost. On Vercel there is
nothing behind `/api` and every call would 404.

Vite inlines `VITE_*` at build time, so changing one requires a redeploy.

---

## 3. Admin console on Vercel

A **second** Vercel project, same repo, root directory `admin`.

| Variable | Value |
|---|---|
| `VITE_ADMIN_API_BASE` | `https://<your-api>.onrender.com/api` |

Then put real access control in front of it — Vercel password protection,
an SSO proxy, or an IP allowlist. `admin/vercel.json` sets `noindex` and
`X-Frame-Options: DENY`, but those are courtesies, not access control.

---

## 4. Wire CORS back

Once both Vercel URLs exist, set them on Render:

```
CORS_ORIGIN=https://leenk.vercel.app,https://leenk-admin.vercel.app
```

Behaviour:

- listed origin → gets `Access-Control-Allow-Origin`
- unlisted origin → header omitted, logged as `[cors] blocked origin: …`,
  and the browser blocks the request
- no `Origin` header (Render's health probe, curl, Capacitor) → allowed,
  because CORS is a browser mechanism and blocking these would break the
  health check and the native build

If `CORS_ORIGIN` is unset in production the API allows everything and warns
loudly at boot. That is a deliberate fail-open so a misconfiguration doesn't
take the app down — but it should never ship that way.

## Verifying a deploy

```bash
curl https://<api>.onrender.com/health
# {"status":"ok","store":"firestore",...}   <- "memory (dev)" means Firebase is unset

curl -H "Origin: https://leenk.vercel.app" -i https://<api>.onrender.com/health | grep -i access-control
# access-control-allow-origin: https://leenk.vercel.app

curl -H "X-Admin-Key: $ADMIN_KEY" https://<api>.onrender.com/api/admin/health
```

Check the Render boot log for:

```
[leenk] store: firestore
[leenk] cors: https://leenk.vercel.app, https://leenk-admin.vercel.app
```

Any `WARNING` line there is a real misconfiguration.

## Capacitor

`VITE_API_BASE` must be absolute for native builds too — a packaged app has no
dev proxy. Native requests send no `Origin` header, so they are unaffected by
`CORS_ORIGIN`.

```bash
npm run build && npx cap sync
```
